# v3.5.0 行为回归测试

只在维护、升级或系统测试 Skill 时读取。测试可观察决策和生成结果，不要求输出固定措辞。

## 使用方法

对每个案例检查：

1. 是否保留用户明确意图；
2. 是否只选择一个主笔触；
3. 构图、画布、配色和效果是否处在正确维度；
4. 是否守住参考风格边界；
5. 是否发生对应的禁止漂移；
6. 直接生图、提示词、诊断等输出动作是否正确。

## 核心案例

| 编号 | 输入 | 必须出现的行为 | 禁止漂移 |
|---|---|---|---|
| E01 默认男性 | “画一个冷淡短发动漫男生。” | 定向圆珠笔、参考内受控单色、视觉纯白数字画布、无文字 | 所有默认图机械锁死皇家蓝、彩铅、暖纸、完整场景、角色姓名 |
| E02 温柔女性 | “画一个安静温柔的长发女孩。” | 情绪改变表情和线条节奏；可选轨道纠正线 | 因“温柔”触发暖黄纸、水彩、柔焦 |
| E03 情侣接触 | “画一对害羞情侣，只有额头接触。” | 进入精确模式；用一个允许触点和一个主要分离区表达，负面约束保持短小 | 额头仍有空隙、脸部融合、把全部微几何诊断复制进提示词 |
| E04 动作少年 | “少年挥刀冲向镜头，要有速度。” | 尖锐动作线；轴线起点、受力关节、终点和空白通道明确 | 四周均匀爆炸、第二组射线、圆环主导、动作不可读 |

| E10 指定文字 | “左边写‘夏日未完’，不要别的字。” | 只出现准确文案并规定位置权重 | 多余字符、署名、水印 |

| E12 只要提示词 | “给我一个这种风格的女生提示词。” | 输出方案、完整提示词、必要负面约束 | 未经要求直接生图、展开参数教程 |
| E13 直接生图 | “画五条悟，酷一点，直接出图。” | 内部自动导演并调用图像生成能力 | 停下来要求填写选项表 |
| E14 返图诊断 | “这张图为什么不像参考风格？” | 依据可见证据指出一个主要偏差和优先修正 | 未经要求直接重做或臆测原始 prompt |
| E15 角色主色情侣 | “画炭治郎和香奈乎的双人关系图，自动配色。” | 分别从两名角色可靠主色建立个人线场 | 机械套用冷蓝／暖橙、完整赛璐璐上色 |
| E16 原创情侣配色 | “画一对原创恋爱动漫情侣，没有指定颜色。” | 根据角色设计选择单色、相邻色或克制后备双色 | 把冷蓝／暖橙当唯一答案、随机彩虹 |
| E17 连续默认颜色 | 连续生成男性、女性、情侣、动作人物和海报 | 在参考内墨色和点色中出现受控变化 | 五张全部机械皇家蓝、为求变化漂成彩铅或黄纸 |
| E18 自然亲密接触 | “画一对近距离对视的情侣，头顶和刘海轻触，女生拉住男生衣领。” | 头发相切与手指—衣领形成两个清楚关系节点，鼻唇留窄白缝，不强制露额 | 因额头未露而判失败、删除衣领接触、脸部融合、鼻唇误接触 |
| E19 近接触张力 | “画一对即将接吻的情侣，脸很近但不要碰到。” | 鼻尖和嘴唇之间保留连续狭窄的纯白负空间，以姿态和视线表达张力 | 强行补成额头或鼻唇接触、距离过远、共享线团填满脸间留白 |
| E20 普通静态动作 | “男生靠在栏杆边，一只手插兜。” | 只写支撑位置、身体方向和手部任务 | 强行展开肩肘腕全关节轴线、加入速度线 |
| E21 搜索线与无接触 | “两人脸靠得很近，但任何地方都不要碰。” | 两人之间形成连续白色关系通道，辅助寻找线在通道外终止 | 一边要求自由越界线，一边逐项禁止所有身体部位造成冲突 |
| E22 模糊亲密关系 | “画一对很亲密的情侣对视。” | 选择一个自然关系机制，以姿态和视线优先，不固定露额或节点数量 | 同时列出额头、刘海、头顶、肩部、衣领等全部候选触点 |
| E23 提示词压缩 | 任一普通单人或双人提示词 | 一个主成立点、一个动作／关系机制、一个主笔触机制、2–4 组负面漂移 | 把导演闸门、L0–L4、D0–D4 和完整验收清单逐项输出 |

## 标题海报案例

| 编号 | 输入 | 必须出现的行为 | 禁止漂移 |
|---|---|---|---|
| T01 普通无字海报 | “画一个人物靠右、左侧留白的横版角色海报。” | 普通海报构图，左侧保持无字纯白负空间 | 自动角色名、作品名、日文、签名 |
| T02 默认沿用输入 | “画明日香，做成带名字的标题海报。” | 一级标题沿用“明日香”；二级省略；自动选择一种版式 | 擅自改成 `ASUKA` 或日文、强制询问语言菜单 |
| T03 精确英文 | “左侧标题只写‘ASUKA’，保持这个大小写。” | 一级逐字使用 `ASUKA`，只出现这一组文字 | 改大小写、补作品名、账号或额外字符 |
| T04 明确日文 | “主标题使用我提供的日文‘アスカ’。” | 逐字使用用户提供的准确日文 | 改写日文、加入伪假名或三语标题 |
| T05 按作品适配 | “画明日香，标题语言按作品自动选择。” | 有把握时选择可靠的短官方识别形式；无把握时回退“明日香” | 为日系感编造日文、把不确定译名当事实 |
| T06 双层上限 | “主标题‘ASUKA’，下面写‘EVANGELION’。” | 只有两级；一级明显、二级更小更轻 | 第三级日期、时间、版权条、坐标 |
| T07 无依据编号 | “画一个普通原创女高中生，做角色档案版。” | 因缺少可用一级文字，只问“一级标题写什么？”；得到标题后，没有可靠代号则省略二级 | 把人物类别当姓名、随机 `NO.07`、日期、坐标或实验编号 |
| T08 官方代号 | “画 Zero Two，一级写‘ZERO TWO’，二级写‘CODE:002’。” | 两级内容逐字准确；二级作为较弱官方代号 | 把编号扩展成随机数据面板或 UI |
| T09 情侣双标题 | “画堀京子和宫村伊澄，名字分别放在两人外侧。” | 两个人名分别归属人物；中心关系焦点无字；一个版式 | 名字交叉归属、标题遮挡脸／手／触点、重复二级 |
| T10 动作轴标题 | “少年挥刀，标题‘BREAK’顺着挥刀方向。” | 标题服从唯一动作轴，可有限遮挡且仍可读 | 第二文字轴、标题与速度线打架、四周爆线 |
| T11 高准确度 | “标题必须完全准确，可以直接发布。” | 优先无字母稿＋确定性排版＋检查；能力不足时如实说明 | 声称仅靠生图提示词已保证逐字准确 |
| T12 标题白底 | “做带名字的纯白底角色海报。” | 加字后仍使用中性均匀 #FFFFFF 数字画布 | 黄白纸张、纸纹、折痕、扫描底色 |
| T13 署名安全 | “画明日香的名字海报。” | 只使用被触发的角色标题 | `by xxx`、作者签名、水印、账号、品牌 |
| T14 长标题降级 | “把一大段中文台词完整放进海报里。” | 说明模型内长文字风险；缩短一级／省略二级或改走后期排版 | 强塞长文造成乱码并声称准确 |
| T15 中文题字骨架 | “画雪乃的名字海报。” | 一级“雪乃”使用同墨书写动势，两个字不共享方框、重心或基线，整组形成非矩形轮廓且准确可读 | 仅给标准楷体加毛边、等大字框、标题笔画与人物割裂 |
| T16 英文重复字母 | “五条悟海报，左边写‘GOJO’。” | 字母帽高、宽度、横杠和基线明显不齐；两个 `O` 同属一手但起点、弧度或收笔不同 | 圆润字库体、复制式 `O`、完美基线、只靠排线假装手写 |
| T17 竖排与情侣题字 | “画堀京子和宫村伊澄，姓名分别竖排在两侧。” | 两侧沿用人物线色并属于同一题字家族；字符占宽与竖排中心自然变化，中心关系区无字 | 等距隐形字格、两套无关字体、文字遮挡关系焦点 |
| T18 精确文字的风格一致性 | “标题必须完全准确且可以发布，但要像画师随手题写。” | 无字母稿＋可验证后期；准确文字仍匹配人物线色和非矩形题字骨架，能力不足时说明限制 | 用默认系统字体覆盖后声称风格通过、用生成式编辑冒充确定性 |
| T19 单标题不补信息 | “画明日香，只写‘ASUKA’。” | 只出现一级；用一级自身的起止、越界或题字轨迹建立视觉锚点 | 为模仿两级成功样例自动补作品名、编号或装饰小字 |
| T20 两级自由度迁移 | “一级‘ASUKA’，二级‘EVANGELION’。” | 一级承担非矩形自由题字，二级以更小窄字承担信息稳定；仍只出现两级 | 一级退化为字库、服装自动出现 `02`、第三层信息 |
| T21 用户规整覆盖 | “标题‘NOVA’，明确使用规整极简印刷体。” | 关闭默认题字骨架，逐字服从正式印刷体方向 | 为守默认风格强行加入歪斜、重描或涂鸦 |

## 已知故障专项

### 黄白背景

输入：“画一个简单的动漫男生，不要背景。”

通过条件：

- 明确使用视觉语法中的纯白数字画布视觉合同；
- “不要背景”被解释为无场景但仍有不透明纯白画布；
- 无纸色、纸纹、扫描颗粒、暗角或光照染色。
- 视觉中性的 252–255 近白不因数值浮动单独判为风格失败；只有用户明确要求技术纯白时才做背景归一化和逐像素检查。

### 彩铅／精致插画漂移

输入：“安静、青春、像恋爱动画里的男生。”

通过条件：

- 情绪只影响姿态、表情和线条节奏；
- 默认仍是参考范围内的受控单色圆珠笔式结构线与排线；
- 不自动加入肤色、夕阳、暖光、彩铅、水彩或完整背景。

### AI 毛线团

输入：“线稿更手写、更乱一点。”

通过条件：

- 不直接堆叠“更乱、更多 scribble”；
- 优先增加贴结构的纠正线、笔压差和方向性；
- 主轮廓、眼睛、手与接触点保持清楚；
- 不出现同半径线圈、等距波浪和跨物体缠绕。

### 双人唯一接触

输入：“两人额头轻触，其他地方不要碰。”

通过条件：

- 进入高难度精确接触模式，但不把它当普通情侣默认；
- 正向描述一个允许触点和一个主要分离区；
- 提示词不穷举刘海、发际线、发饰、每根发丝和全部身体部位；
- 返图后只针对实际失败追加一条局部修复。

### 单一动作轴

输入：“少年挥刀冲向镜头，要有速度。”

通过条件：

- 明确轴线起点、经过的肩肘手腕或其他受力关节，以及刀尖／拳头等终点；
- 主要速度线与轴线平行、向终点汇聚或顺轴延伸；
- 轴线两侧存在低密度空白通道；
- 不出现第二组主轴、四周径向爆线或包围主体的爆炸中心。

### 角色主色双墨

输入：“画两个具名动漫角色的情侣或关系图，自动配色。”

通过条件：

- 用户指定颜色优先；
- 否则每个人物从可靠身份信息中选择一个主要识别色作为完整个人线场；
- 冷蓝／暖橙只在角色主色不明确时作为后备方案；
- 两套颜色不混成第三色，不扩散成完整彩虹上色。

### 像素级纯白

输入：“背景文件必须每个像素严格为 #FFFFFF。”

通过条件：

- 生成提示词仍要求视觉中性纯白；
- 明确说明提示词本身不能保证逐像素数值；
- 生成后执行确定性背景归一化并检查像素，或在无法执行时如实说明未满足技术合同。

### 假手写字库

输入：“标题已经有毛边和重描，但看起来还是手机系统手写字体。”

通过条件：

- 忽略毛边、排线和墨色，只检查字形骨架与整组外轮廓；
- 统一字框、帽高、基线、竖排中心或复制式重复字符任一明显成立即判失败；
- 修正只处理题字区域，重建一个整组动势和非矩形字符关系，不重做人物；
- 不以“艺术字体、更加随性、再乱一点”等抽象形容词作为主要修正。

## 验收

升级至少满足：

- E01–E23 的导演决策全部通过；其中 E03、E18、E19 分别覆盖明确唯一接触、自然亲密接触和近接触张力，E20–E23 覆盖动作骨架、线条冲突与编译压缩；
- T01–T22 的标题导演决策全部通过，尤其守住普通海报默认无字、两级上限、语言回退、编号真实性、关系保护区、高准确度降级、题字骨架和用户字体覆盖；
- 八个专项都能指出明确、可观察的通过条件；
- 不依赖特定标题、固定段落数量或正则措辞；
- 没有为了单个案例增加会伤害其他任务的通用绝对规则。

# 自动导演工作流

本文件负责把用户需求转换成风格内决策。视觉事实以 [视觉语法](visual-grammar.md) 为准；需要模式细节或示例时再读 [模式与示例](modes-and-examples.md)。

## 1. 先判断任务

按用户真正要的交付路由：

- **提示词**：输出完整中文提示词和当前必要的负面约束。
- **直接生图**：内部编译提示词后调用可用的图像生成能力。
- **严格同母稿变体**：用户明确“同一母稿／只改某项”时，固定人物、动作和线层，再生成或描述 2–4 个单变量版本。
- **同系列创作变体**：固定共同视觉 DNA、身份、画布和笔触基线，以差异矩阵设计多个不重复但同系列的人物事件。
- **系列角色组图**：固定共同视觉 DNA 和系列关系，为不同角色建立差异矩阵，并保护逐张身份与主色。
- **方向比较**：给最多三个口语化方向，说明画面差异。
- **帮助／介绍**：解释一句话用法、能力范围和可选方向。
- **返图诊断**：只根据可见结果判断最主要偏差，不擅自修改。
- **风格反推**：描述可见视觉机制，再给重建提示词；不声称恢复原始 prompt。

如果用户同时提出内容和“直接出图”，不要停在提示词交付。

## 2. 锁定用户意图

生成前在内部形成一份最小意图锁：

| 维度 | 优先级 | 缺省处理 |
|---|---:|---|
| 角色／身份锚点 | 最高 | 未指定则用原创动漫人物；具名角色选 2–4 个可靠辨识锚点 |
| 人数与关系 | 最高 | 单人 |
| 动作、表情、视线 | 高 | 与语义一致且区别于系列其他图片的可解人物事件 |
| 关系、接触、遮挡、手部归属 | 高 | 形成一个开放式关系事件；不擅自增加复杂接触、承重或共同持物 |
| 服装与道具 | 高 | 简洁、符合角色锚点 |
| 画幅、景别、裁切 | 中 | 头像或半身，按动作调整 |
| 主墨色与强调色 | 中 | 可靠角色主色或参考内受控单色；信息不足才回退皇家蓝 |
| 笔触强度 | 中 | 主笔触内部默认参考标准；明确清爽才降为轻量，明确密重或题材需要才升为高密 |
| 底色／材质 | 高 | 使用视觉语法中的白底合同 |
| 角色字标／署名 | 高 | 默认无文字；明确要求后按视觉语法的三种文字结构路由 |
| 输出动作 | 最高 | 按用户原话执行 |

用户明确指定的值不可被自动路由覆盖。未知内容采用“语义最小补全、视觉主动导演”：不为了“更有画面”擅自添加场景、道具、剧情、天气、纸张或光效，但可以在已授权主题内主动设计姿态、动作、观看关系、表情、视线和版式变化。自动导演优先用低／中风险姿态实现变化，不主动随机拼装高风险复合动作；用户明确要求的复杂动作不因风险被删除。

## 3. 决定是否询问

默认不询问。满足以下全部条件才问一个最短问题：

1. 缺失信息会明显改变身份、人物关系或核心动作；
2. 两种解释无法同时成立；
3. 从上下文不能合理推断；
4. 任取其一会显著偏离用户意图。

风格、颜色、构图和密度通常由 Skill 自动决定。用户主动要选择时，最多给三个结果导向的口语化方向，不显示内部层级代码。

### 3.1 区分三类系列任务

先按用户措辞判断固定层有多窄：

- **严格同母稿变体**：出现“同一母稿、只换色、只改画幅、横竖方对比”等控制语。固定身份、动作、L0 结构、主笔触和密度地图；每版只改变一个主变量。
- **同系列创作变体**：出现“同系列、变体、多来几张但不要重复”等扩展语。固定共同视觉 DNA、人物身份、#FFFFFF 画布合同、系列笔触基线、配色逻辑和文字授权；构图、景别、身体朝向、主要动作、手部任务、表情视线与文字位置可以联动变化。
- **系列角色组图**：多个角色组成一套海报。除共同视觉 DNA、画布、笔触和文字授权外，再固定必要的系列关系；每张保护自己的身份锚点和可靠主色，并拥有不同人物事件。

同系列创作变体与系列角色组图都先在内部建立差异矩阵。每张至少有一个显著区别于相邻图片的观看关系或人物事件；不要轮流套用固定的“低机位／回眸／抬手／托腮”模板，也不要为了差异而随机拼接互不相干的变量。差异矩阵用于防重复，不是限制每张只能改变一两项。

每张组图都先写一张内部人物事件卡：

```text
主成立点
+ 观看关系与景别
+ 身体朝向与头肩关系
+ 一个主要动作
+ 可见手的左右归属与任务
+ 表情和视线
+ 支持动作链的裁切
```

事件卡必须能被一句自然语言概括，例如“侧身经过时回望，并用靠近镜头的右手把右侧鬓发别到耳后”。如果只能列出一串姿势词，说明变量尚未形成同一事件，应先重新导演。

### 3.2 姿态风险路由

系列差异优先来自机位、景别、人物占比、表情、视线、近侧手任务与构图。自动导演按以下顺序取用：

1. 先用头肩自然同向、正面／三分之四侧面、前倾、坐姿、依靠、整理领口／袖口、近侧手别发／挡光／持物等低风险变化；
2. 需要更强观看关系时，可用轻度回望、手靠近脸、手臂穿过身体中心或明显俯仰，但要补足头肩、手侧与裁切；
3. 身体背向镜头同时大幅回头、反向扭腰同时触脸、远侧手跨身、紧裁切承载复杂手臂、多人手臂交叉并共同持物不进入默认随机池。

第 3 类只有用户明确要求，或其对本张主事件不可替代时才保留；保留后必须经过动作可解链。用户没有指定该高风险姿态时，可换成表达相同情绪或关系的低／中风险事件，不等于把系列退回静态正面。

## 4. 选择配置

先写出一句内部主成立点，例如“角色身份先成立”“挥刀冲势先成立”或“亲密但未接触的张力先成立”。一张图只能有一个主成立点；风格线层、构图、颜色和附加效果都为它服务。

严格使用：

```text
1 个主成立点
+ 1 个主笔触
+ 1 个构图策略
+ 1 个画布/配色策略
+ 0–1 个附加效果
+ 0–1 个经授权文字结构
```

### 主笔触

- 普通、清楚、克制、未指定：定向圆珠笔排线。
- 长发流动、回望、明显作画寻找感：轨道弧线／纠正线。
- 深色长发、局部接近实色：高密发丝场。
- 战斗、速度、攻击性：尖锐动作线。
- 哭泣、惊惧、压迫和强黑白：马克笔暗块＋白刮痕。

情绪不能单独触发外部媒介。比如“温柔”不触发彩铅，“怀旧”不触发黄纸，“酷”不触发 3D 霓虹。

### 笔触强度（主笔触内部）

选择主笔触后再确定强度，但不把它当作新的模式或对外参数：

- 用户明确要干净、少线、清爽或轻淡：轻量；
- 用户未指定：参考标准；
- 用户明确要密、压黑、强烈笔触，或深色长发、强阴影、压迫和高速动作确实需要：高密。

强度调整只进入头发、衣物暗面、投影和动作轴等授权区域。参考标准必须保留一个明显局部高密区和可见的浅淡寻找重描；高密也不能覆盖脸、手、接触点或纯白关系通道。不要因为角色短发、画面安静或提示词需要压缩，就把默认降成普通干净线稿。

### 构图

根据人物关系和动作选择头像、半身、动作方图、人物偏置海报、双人近景、双联画或同母稿横竖方变体。构图不是笔触模式。

双人／多人先设计一个开放式关系事件，不被三种情侣路由限制。内部确定“关系意图 + A/B 位置朝向 + 距离与接触拓扑 + 支撑／重量关系 + 手部／道具／遮挡归属 + 视线情绪 + 裁切”，再只把本图需要的结果编译进提示词。明确接触、自然亲密和近接触张力只是高频处理例子；面对面、并肩、背靠背、头靠肩、扶住、守护、共同持物、对峙或擦肩都可按语义成立。只有用户明确说“只有、仅、其他地方不要碰”时，才进入精确接触模式。

### 画布与配色

先选择一种主配色策略，再在该策略内选择色相。普通单人默认受控单色；单点强调可作为其从属层。线内渐变、选择性平涂、较完整彩色和黑底反相只有用户明确要求，或同母稿变体明确把配色作为单一变量时才启用。

色相按以下优先级选择，不把“未指定颜色”直接等同于皇家蓝：

1. 用户明确颜色；
2. 具名角色可靠的主要识别色；
3. 原创角色由发色、服装大色块和主题推导的一种参考内墨色；
4. 信息仍不足时回退皇家蓝。

具名角色的主要识别色被转译为整套墨线，不自动恢复完整固有色上色。参考内色域包括蓝／深靛、黑／石墨灰、蓝紫／玫粉、红／暖橙／橙棕和青蓝／蓝绿；墨绿只有角色、用户或主题明确支持时才用。单人通常使用一种主墨色和最多一个身份点色。情侣在身份区分重要时优先分别使用双方主要识别色；用户明确要求统一关系色时可共享一种主墨色，只有角色主色不明确且确实需要分色时才使用克制冷暖双色。多人优先共享主墨色并以少量点色区分，禁止随机彩虹分配。黑色墨线仍使用白底，不能误路由成黑底反相。白底以视觉中性 #FFFFFF 为目标。

### 附加效果

默认不用。只有用户明确要求，或效果对动作／关系不可替代时，才选择一种喷溅、半调、错色副线、白刮痕、有限辉光或外围关系弧线。

### 按需文字结构

默认不用。用户明确要求文字后，只选择一种结构：

- “加署名”且没有另给内容：独立作者署名 `ChenLin`；
- “加角色名／把角色名写上去”：独立角色名／角色字标，只使用当前请求中已明确写出的角色名；请求中没有名字时问一个最短问题；
- “加角色名和署名”：一级角色字标＋二级 `ChenLin`；
- 用户给出其他准确文字：逐字使用，不翻译、不改写、不改变大小写，并按其明确用途处理；
- “不要文字／不要署名”：不启用对应文字，排除要求优先。

文字结构不占用附加效果名额，但必须服从主成立点。先完成主体构图和安全留白，再把授权文字与人物线稿一体式生成；不建立无字母稿、透明签名素材或后期叠加步骤。只说“加署名”不触发角色名，只说“加角色名”也不自动附加署名、作品名或 `by`。

## 5. 生图前导演闸门与冲突检查

编译前逐项确认：

1. 用户明确的角色、关系、动作、构图、颜色、背景、角色字标、署名和输出动作是否全部保留？
2. 是否只有一个主笔触？
3. 主笔触内部是否已经路由到轻量、参考标准或高密；默认参考标准是否保留局部高密与寻找重描，而没有全局加线？
4. 是否只选择一种主配色策略；黑色墨线、黑底反相、双联、点色和效果是否被放在正确维度？
5. 是否存在未经用户授权的纸张、彩铅、水彩、柔焦、散景、辉光、完整场景或文字；授权文字是否只使用一个已选结构和准确内容？
6. L0 能否先独立表达人物身份、动作和关系？
7. 脸、手和接触点是否有保护区？
8. 双人／多人是否有独立个人线场与明确遮挡；关系意图、位置朝向、距离／接触、承重、手部／道具归属、视线和裁切是否共同构成一个可读事件？
9. 具名角色是否使用可靠身份锚点和主要识别色，而非机械套用皇家蓝或冷蓝／暖橙？
10. 普通姿态是否只写动作骨架；明显跑跳、攻击或挥击才展开主轴起点、受力关节、终点和空白通道？
11. 是否只选择一个主关系事件；用户要求接触时该动作是否可见，要求不接触时两个人物间是否有连续白色关系通道，未要求“只有”时是否避免擅自施加唯一接触限制？
12. 默认背景是否套用视觉白底合同；若用户要求逐像素 #FFFFFF，是否已计划确定性后处理而非只依赖提示词？
13. 若为同系列创作变体或系列角色组图，是否已建立差异矩阵；本张事件是否与相邻图片有可见区别，而各自需要固定的视觉 DNA、身份、画布、笔触和系列关系仍然一致？
14. 本张动作是否形成同一个事件，而不是身体朝向、回头、抬手、视线和留白位置各自随机选择？
15. 复合姿态中，可见手是否明确属于左侧或右侧，并能沿前臂、肘和上臂回接正确肩膀；当前裁切是否保留或清楚暗示这条连接？
16. 躯干朝向、头肩关系和视线是否兼容；文字安全留白是否只是版式区，而没有反向强迫人物视线或动作？
17. 自动导演是否误把高风险复合姿态当作随机变化；若用户没有指定，该事件能否用低／中风险姿态表达；若用户明确指定，动作可解链是否已经通过？

再检查以下高频冲突：

| 冲突 | 解决方式 |
|---|---|
| 手写寻找线 vs 脸、手、接触或无接触通道 | 保留手写感，但让辅助线在保护区外减弱或终止 |
| 高密发丝 vs 清楚接触节点 | 接触节点优先，高密度退到发根和外侧暗部 |
| 自然亲密 vs 精确唯一触点 | 没有排他措辞时使用自然亲密，不启用精确模式 |
| 近距离构图 vs 完全不接触 | 用连续白色关系通道表达，不逐项枚举所有身体部位 |
| 角色主色双墨 vs 接触处不得混色 | 先保证双方身份可读，触点低纹理；不要求像素级分色边界 |
| 角色主色 vs 系列换色 | 普通具名角色先用可靠主色；只有用户要求系列／变体时才把换色作为单一变量 |
| 黑色墨线 vs 黑底反相 | “黑色线稿”仍为白底；只有明确说黑底、反相或发光才改变画布 |
| 线内渐变 vs 纯白背景 | 颜色只在人物线层或授权区域迁移，不给背景添加渐变或色雾 |
| 动作自然度 vs 全关节几何 | 普通动作只留支撑、方向和手部任务；高速动作才展开轴线 |
| 系列变化 vs 同母稿单变量 | 先路由任务：只有严格同母稿变体执行单变量；创作变体与角色组图允许多变量联动，但每张必须形成一个人物事件 |
| 自动变化 vs 高风险复合姿态 | 先用机位、景别、表情、近侧手任务与低／中风险姿态制造差异；高风险组合不进入默认随机池 |
| 用户明确回眸／转身 vs 头颈与躯干连续 | 保留用户动作，明确身体朝向和头肩关系；必要时减小回转幅度或扩大景别，不改成静态正面 |
| 抬手触脸／别发 vs 手臂归属 | 明确左右手、同侧耳／脸及可见肘肩路径；若裁切无法承载则扩大景别或改用近侧手 |
| 人物偏置／标题留白 vs 视线方向 | 留白服从人物事件；不因人物位于一侧就自动命令视线朝向另一侧 |
| 角色字标／署名 vs 人物焦点 | 先保脸、眼睛、手、接触点和动作轴，把文字移入人物外侧安全留白并降低权重 |
| 角色名 vs 自动翻译／别名 | 逐字沿用当前请求中的名字；请求中没有名字时问一个最短问题，不编造日文或罗马字 |
| 角色名＋署名 vs 多级海报排版 | 只保留一级角色字标和二级 `ChenLin`，删除作品名、编号、日期、账号和第三层信息 |

发现冲突时，以“用户明确要求 → 角色身份 → 肢体连续与人物关系 → 本张人物事件 → 构图与视线 → 风格与配色 → 文字与效果”的顺序取舍。先保留用户明确要求，让自动选择的从属变量服从身体可解性；用户未指定的高风险组合可以换成表达同一事件的低／中风险方案，用户指定的复杂动作则重新安排人物位置、手的侧别、回转幅度、视线或景别使其可解。若用户明确给出的多项要求本身无法同时成立，按意图锁规则问一个最短问题。任何一项失败，先修内部配置，不进入提示词编译或生图。

## 6. 提示词编译与压缩

内部可以完整检查所有模块，最终只编译本图实际选中的内容。写成一个连续中文自然语言段落，按五段逻辑压成一条执行链：

```text
角色身份与本张人物事件
→ 构图、观看关系与一个动作骨架／关系机制
→ 一个主笔触及其结构性线行为
→ 配色与画布
→ 经授权的一种文字结构
→ 当前最相关的少量防错
```

编译规则：

- 每张图只写一个主成立点、一个动作／关系机制和一个主笔触机制；未选中的候选动作、接触位置、线层和效果不进入提示词。
- 普通动作使用“支撑／依靠位置 + 整体方向 + 手部任务”的骨架；只有高速动作才写轴线起点、关键受力位置和终点。
- 复合姿态按需要补充“身体朝向 + 头肩关系 + 左右手归属 + 可见肘肩路径 + 支持动作的裁切”，再压缩为一到两句自然动作；不输出逐关节说明书，也不只写模糊的“动态姿势”。
- 同系列创作变体与系列角色组图逐张编译事件卡，允许构图、动作、表情、视线和文字位置联动变化；只有严格同母稿变体执行单变量限制。
- 关系描述优先写一个正向、可观察的主事件及必要拓扑。亲密关系写“如何亲密且仍可分辨”，近而不触写“连续白色关系通道”，精确接触只写一个允许触点和一个主要分离区；对峙、协作、守护、并肩或背靠背则写清位置、承重、手／道具归属和视线中的相关部分，不套情侣词。
- 自动导演的低／中风险姿态只编译完成事件所需的动作骨架；用户明确指定的高风险姿态再补足动作可解链，并压缩为一到两句。
- L0–L4、D0–D4 和质量闸门只用于内部推理；最终转写成一到两句可观察的线条与密度行为。
- 参考标准强度的提示词必须保留一句等价的核心笔触机制，优先压缩为：“头发与衣物暗部形成明显的方向性密集排线，发缘和肩线保留浅淡、不规则偏移的寻找重描，脸部与手指保持干净低纹理。”可按人物可见范围替换“衣物／肩线／手指”，但不得在压缩时同时删掉局部高密、浅淡寻找线和焦点保护三层信息。
- 同一概念通常只出现一次；确有高风险时可在负面约束中再出现一次，不用同义词连续重复。
- 没有使用的线层、效果、文字和修复规则不要硬塞。过去案例的验收细节不得自动变成新图的通用要求。
- 已授权文字只编译一个结构：写清准确内容、主次层级、与人物共享的墨色、负空间位置和手绘笔势；不只写笼统的“艺术字体”，也不把完整文字合同逐条复制进提示词。

### 负面约束

负面约束只保留当前画面最可能发生的 2–4 组漂移。优先选择：结构性乱线、当前关系／动作错误、当前媒介漂移、当前画布漂移。不要默认复制完整通用清单。

例如普通白底人物可使用：

```text
无结构归属的随机线团；五官和手部被密线遮挡；普通精修线稿或完整赛璐璐上色；黄白纸张、纸纹和未经授权文字。
```

双人图把其中一组替换为当前最可能的关系错误；动作图替换为第二主轴或四周爆线；黑底图替换为 3D 霓虹和宽辉光。已经授权文字时，不再笼统禁止“文字”，而是只禁止错字、多余字符、系统字体感或遮挡焦点。不要禁止当前模式必需的长弧、暗块、点色或平涂。

### 编译后压缩闸门

交付前再问：

1. 删除任一句后，画面机制是否完全不变？若是，删除。
2. 是否出现了未被选中的动作、接触候选或附加效果？若是，删除。
3. 是否用三个以上近义否定词描述同一个失败？若是，只留最直接的一条。
4. 是否把诊断或验收步骤写成了模型必须逐项执行的长清单？若是，改回一个正向画面结果。

## 7. 输出动作

- 用户只要提示词：交付风格方案、完整提示词、负面约束；不要附教程。
- 用户明确要生图：使用编译后的完整提示词直接生成，以图片为主要结果。
- 用户明确要同一母稿或“只改某项”：固定人物、动作、L0 结构和密度地图，每版只改变构图、配色、底色或效果中的一个变量。
- 用户要同系列创作变体：固定共同视觉 DNA、身份、画布、笔触和配色逻辑，再按差异矩阵联动变化构图与人物事件。
- 用户要多角色系列：除共同视觉 DNA 外保护逐张角色身份与主色，再生成不同但自洽的人物事件；不要套用严格母稿的单变量规则。
- 用户要诊断：先指出一个主要失败及其可见证据；用户要求修复后再重写或生图。

## 8. 生图后质量闸门

按优先级检查：

1. **身份与关系**：人物是否可识别，动作、视线、遮挡、手和接触是否正确；系列中本张事件是否与其他图片有可见区别。
2. **主轮廓**：脸、五官、发型大形和手势是否能脱离乱线独立读出。
3. **线条归属**：密线是否跟随发束、衣褶、投影或动作轴。
4. **手写自然度**：是否有不规则停顿、重描和笔压差，而非机械卷曲。
5. **笔触强度与密度层级**：所选强度是否成立；默认参考标准是否有一个明显局部高密区、可见寻找重描和干净焦点，而不是过净或全局铺线。
6. **风格边界**：是否漂成彩铅、水彩、普通精修动漫、厚涂或 3D。
7. **动作与关系**：动作图是否只有一个优势轴；关系事件的位置、距离、承重、手／道具归属与视线是否可读；中／高风险姿态中每只可见手是否能沿前臂、肘、上臂连接到正确肩膀，头颈是否连续回接躯干，裁切是否支持动作；明确接触是否真的相切，近接触是否保留用户要求的窄白负空间。
8. **颜色身份**：是否只有一种主配色策略；具名角色的主墨色是否来自可靠角色主色；黑色线稿是否仍为白底；情侣是否避免机械冷蓝／暖橙；渐变与平涂是否只进入授权区域。
9. **画布与文字**：白底是否视觉中性、均匀且不透明，是否出现纸纹、可见色偏或未经授权文字；若文字已授权，是否内容准确、只有一个实例、结构层级正确、位于安全留白且保持自然手写笔势；只有用户要求技术纯白时才检查逐像素 #FFFFFF。

## 9. 单变量修正

每个请求资产在初次生成后只有一次自动重试额度。质量闸门发现一个或多个问题时，先按“身份与关系 → 主轮廓 → 用户明确要求 → 风格与装饰”的优先级选择最主要的一个可见失败，再用这唯一一次重试做单变量修正；不要为了同时修完所有问题把提示词改成互相打架的清单。

系列／多图任务按每个请求资产分别计算重试额度：首轮通过的图片保持不变，只有失败图片可以各自重试一次。初次生成不计为重试，因此未经用户再次授权，每个资产最多产生初稿和一张修正版。

唯一一次重试可使用以下首要修正：

| 失败 | 首要修正 |
|---|---|
| 人物或关系不成立 | 修 L0、姿态、遮挡和接触，不先加线 |
| 像 AI 毛线团 | 删除无归属线，重新分配 L1/L2/L3 方向和权重 |
| 太像普通干净线稿 | 恢复参考标准成立句：在授权暗部增加方向性 L1，并补回贴结构的浅淡 L2 偏移与笔压差，不增加随机线 |
| 笔触整体过淡、没有密度锚点 | 只在头发、衣物暗面或动作轴选一个主高密区加深，脸手不变 |
| 笔触全局过密或像机械网纹 | 退回参考标准，把高密收束到一个结构区域，打散线长、间距与重描偏移 |
| 五官或手被覆盖 | 恢复 D0 保护区，降低穿越线权重 |
| 全画面同密度 | 把高密限制到发根、暗面或动作边缘 |
| 动作线四周放射 | 固定主轴起点和终点，删除其他方向射线，只保留平行、汇聚或顺轴延伸的线 |
| 回眸导致头颈／躯干断裂 | 保留回眸事件，正向重申身体朝向和头肩连续，只调整回转幅度或景别；排除头颈断裂，不改成静态正面 |
| 抬手触脸／别发导致手臂错接 | 保留手部任务，锁定左右手及同侧目标，正向重申手—前臂—肘—肩连接并让裁切保留该链；排除悬空手掌、多余手臂和错误肩部归属 |
| 系列姿态重复 | 只重做该资产的人物事件与动作层，依据差异矩阵换观看关系、身体朝向或手部任务；共同视觉 DNA、角色身份和已成立风格不变 |
| 自动导演加入高风险姿态导致肢体问题 | 保留本张情绪与关系意图，改用低／中风险的机位、景别、近侧手任务或头肩同向动作；共同视觉 DNA、身份和配色不变 |
| 用户明确高风险姿态导致肢体问题 | 不删除用户动作；只调整回转幅度、手的侧别、人物位置或景别，使动作可解链连续 |
| 明确要求接触但仍有空隙 | 只移动相关部位，直到用户指定的部位与材质形成真实相切；只有用户明确要求“只有”时才删除其他接触节点 |
| 普通亲密构图被强制露额 | 恢复符合语义的头顶／刘海／发际轻触或手与衣物接触，不把裸露额头当通用模板 |
| 即将接吻却意外接触 | 重新打开鼻尖与嘴唇之间连续、狭窄的纯白负空间，保留靠近姿态与视线张力 |
| 情侣颜色机械蓝橙 | 恢复两名角色各自可靠主色；只有主色不明时才使用关系后备配色 |
| 黑色线稿误变黑底 | 恢复 #FFFFFF 画布，只保留黑／石墨灰墨线；不改变人物和主笔触 |
| 渐变污染背景 | 锁定背景为 #FFFFFF，只在线层或人物授权区域保留渐变 |
| 局部平涂扩散成全彩 | 恢复允许上色白名单，其他区域退回主墨线和纯白负空间 |
| 情绪图漂成彩铅／暖纸 | 恢复默认墨线与白底合同，不改变表情和姿态 |
| 白底黄白或有纸纹 | 只修视觉画布合同，删除实体纸张和光照染色词；像素级纯白需求另走确定性后处理 |
| 双人粘连 | 修两套个人线场、遮挡和纯白分界 |
| 黑底变 3D 霓虹 | 缩窄辉光，恢复手写线压和线密度塑形 |
| 未经授权出现文字 | 删除所有文字触发词并声明默认无文字 |
| 授权文字内容错误或出现多余字符 | 锁定准确文本，只修文字内容与唯一实例，人物、构图、颜色和笔触保持不变 |
| 署名／角色字标像系统字体 | 保留内容和位置，改写为有起停、连笔、基线起伏、字距差和自然收笔的手绘字标；不使用笼统“艺术字体” |
| 角色名＋署名层级失衡 | 保留角色名为一级，把 `ChenLin` 缩为其 20%–35% 并靠近侧下方；删除第三层文字 |

修正版完成后重新过一次质量闸门。若仍有原问题、出现新问题，或其他已存在的问题尚未解决，立即停止：不再自动生成第三版，不级联修下一个变量，不改用其他生成方式，也不用后期处理伪装通过。最终交付中明确说明已尝试的一次修正和仍可见的问题；只有用户随后明确要求继续，才开始新的修正尝试。
